## Gate Review النوعي

### 1. بساطة التنقل

التنقل ثابت في ست وجهات مبنية على نية المستخدم: الرئيسية، تحليل صفقة، استكشاف السوق، المقارنة، التقارير، البيانات والمنهجية. الدور يغير السؤال وترتيب البداية، ولا يغير أسماء الوجهات. الخريطة تظل طريقة عرض داخل استكشاف السوق، وإنشاء التقرير يبقى داخل التقارير.

### 2. First-Visit

المهام الخمس الأساسية لها تسمية مباشرة ووجهة واحدة متوقعة: شراء عقار → تحليل صفقة؛ فهم حي → استكشاف السوق؛ نظرة أولى → الرئيسية؛ مقارنة حيّين → المقارنة؛ التحقق من رقم → البيانات والمنهجية. يسجل الـharness أول نقرة فقط ويعطي PASS أو REVIEW.

### 3. Scope وKPI

مدخلات العقار والتمويل مستقلة عن Scope السوق. كل KPI حاسم يظهر مع تصنيف منهجي؛ Opportunity Score وProperty Score موصوفان كـInference داخل cohort، والتوقع لا يتقدم على الفعلي ولا يستخدم «الثقة» بدل جودة الاختبار الرجعي.

### 4. حالات عدم الأهلية

تم تصميم حالات غياب البيانات والمقارنة والتوقع والتعارض قبل الانتقال إلى Figma، لذلك لا يعتمد التدفق على الحالة المثالية وحدها.

### 5. Mobile

لا تُخفى وجهة أو وظيفة. يتحول التنقل إلى ترتيب مضغوط، وتتحول المقارنة إلى بطاقات متتابعة، وتبقى الخريطة مرتبطة ببديل قائمة يعرض القيم نفسها.

## قرار الانتقال إلى Figma

**مسموح.** ينقل إلى Figma الـLow-Fidelity المعتمد كما هو، دون هوية بصرية، دون Design System عالي الدقة، ودون Features جديدة. يبقى الاختبار البشري الفعلي شرطًا قبل High-Fidelity وليس قبل نقل هذه المرحلة إلى Figma.
