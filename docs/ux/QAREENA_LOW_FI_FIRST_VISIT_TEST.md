# Qareena Low-Fidelity — First-Visit Test Gate

**النطاق:** Global Shell، الرئيسية، تحليل صفقة، استكشاف السوق  
**النوع:** Expert cognitive walkthrough + first-click test harness  
**الحالة:** Provisional PASS قبل استكمال بقية الـ22 Wireframe  
**ملاحظة:** هذه محاكاة خبراء وليست دراسة قابلية استخدام بمشاركين فعليين.

## فرضية الاختبار

يجب أن يستطيع الزائر الجديد اختيار الوجهة الصحيحة من أول نقرة اعتمادًا على اسم المهمة، دون فهم بنية البيانات أو معرفة أسماء الأدوات الحالية.

## المهام ونتيجة المراجعة

| المهمة | الوجهة المتوقعة | سبب وضوحها | النتيجة |
|---|---|---|---|
| أريد معرفة هل أشتري عقارًا محددًا | تحليل صفقة | الاسم يطابق الكيان والقرار مباشرة | PASS |
| أريد فهم حركة السوق في حي | استكشاف السوق | يفرق بوضوح بين السوق والصفقة | PASS |
| أريد نظرة سريعة قبل اختيار مسار | الرئيسية | لا يفترض معرفة مسبقة | PASS |
| أريد مقارنة حيّين | المقارنة | فعل مباشر مستقل عن الاستكشاف | PASS |
| أريد التحقق من مصدر رقم | البيانات والمنهجية | يجمع المصدر والتعريف والقيود | PASS |

يتضمن الـwireframe أداة First-Click تفاعلية تسجل أول وجهة فقط، وتعيد PASS أو REVIEW دون منح المستخدم فرصة تصحيح قبل تسجيل النتيجة.

## Cognitive Walkthrough

### 1. هل يعرف الزائر ماذا يفعل أولًا؟

نعم، لأن الرئيسية تبدأ بثلاثة أفعال واضحة: حلّل صفقة، استكشف السوق، وقارن بدائل. لا تبدأ برسوم أو أسماء داخلية.

### 2. هل أسماء التنقل متوقعة؟

نعم، بعد إزالة أسماء الأدوات والوسائل مثل «خريطة الرياض» و«AI Report Generator» من المستوى الأول. كل اسم يمثل نية مستخدم.

### 3. هل يمكن تمييز السوق عن الصفقة؟

نعم. تحليل صفقة يستخدم مدخلات عقار وتمويل مستقلة، بينما استكشاف السوق يستخدم Scope جغرافيًا وزمنيًا مشتركًا.

### 4. هل الدور يربك التعلم؟

لا في النموذج المقترح. الدور يغيّر السؤال ونقطة البداية، ولا يعيد تسمية الوجهات.

### 5. هل يعرف المستخدم نطاق الرقم؟

نعم مبدئيًا. Global Shell يعرض النطاق، آخر فترة، والمصدر في شريط ثابت قبل محتوى الصفحة.

## فحص بساطة التنقل

| القاعدة | الحد | النتيجة |
|---|---:|---|
| عدد الوجهات الأساسية | ≤ 6 | 6 — PASS |
| مستوى الوصول إلى المهمة الأساسية | نقرة واحدة | PASS |
| عدد أدوات المهمة في رأس الرئيسية | 3 | PASS |
| أسماء متغيرة حسب الدور | 0 | PASS |
| وجهات مكررة للخريطة أو التقرير | 0 في المستوى الأول | PASS |
| خلط فلاتر السوق بمدخلات الصفقة | 0 | PASS |
| استخدام Emoji كاسم تنقل رئيسي | 0 | PASS |

## المخاطر التي يجب مراقبتها في الاختبار البشري

1. «الرئيسية» اسم عام؛ يجب أن تبقى أفعال البداية الثلاثة فوق أي KPI.
2. قد يخلط بعض المستخدمين بين «استكشاف السوق» و«المقارنة». يجب أن يبقى الفرق: الأول لاكتشاف مرشحين، والثاني لمقارنة قائمة مختارة.
3. ست وجهات على الهاتف تحتاج اختبارًا فعليًا؛ الـlow-fi يعيد ترتيبها إلى شبكة 2×3 دون إخفاء أي وجهة.
4. «البيانات والمنهجية» اسم دقيق لكنه طويل؛ لا يختصر إلى «مصادر» لأن الصفحة تشمل التغطية والتعريف والأهلية أيضًا.
5. يجب اختبار ما إذا كان الوسيط يفهم «تحليل صفقة» بوصفه تحليل عقار العميل، لا صفقة مالية مجردة.

## قرار البوابة

**Provisional PASS.** يسمح بالانتقال إلى Wireframes المقارنة والتقارير والبيانات والمنهجية وحالات النظام، بشرطين:

- عدم تغيير أسماء الوجهات الست أثناء بقية العمل.
- تنفيذ First-Click Test بمستخدمين فعليين قبل High-Fidelity، خصوصًا على الهاتف ولأدوار الوسيط والمطور والباحث.

لا توجد حاجة لإضافة Feature لمعالجة أي مشكلة ظهرت في هذه الجولة؛ التعديلات المطلوبة هي في ترتيب المحتوى والتسمية فقط.
