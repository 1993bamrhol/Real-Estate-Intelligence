# Qareena Information Architecture & UX Blueprint

**الحالة:** Blueprint v1 — جاهز للتحويل إلى Low-Fidelity Wireframes  
**المرجع:** واجهة Qareena الحالية بعد اعتماد Metric Remediation & Governance  
**النطاق:** إعادة تنظيم القدرات الموجودة فقط؛ لا يتضمن تعديل كود أو إضافة Features  
**تاريخ المراجعة:** 2026-09-01

## 1. قرار الـBlueprint

تعاد صياغة Qareena كمساحة قرار عقاري لها ست وجهات ثابتة:

1. الرئيسية
2. تحليل صفقة
3. استكشاف السوق
4. المقارنة
5. التقارير
6. البيانات والمنهجية

الخريطة تصبح **طريقة عرض داخل استكشاف السوق**، ومولدات التقارير تتجمع داخل **التقارير**، ومحتوى «المنصة والباقات» يخرج من مساحة العمل إلى صفحة تعريف عامة. اختيار دور المستخدم يغيّر الصفحة الافتراضية وترتيب الأولويات والنص الإرشادي، لكنه لا ينشئ تنقلًا مختلفًا أو أسماء صفحات متغيرة.

## 2. حدود المرحلة

### داخل النطاق

- جرد الحالة الحالية.
- خريطة المعلومات والتنقل.
- هرم المحتوى داخل كل صفحة.
- نموذج الكيانات والمصطلحات.
- تدفقات المستخدم الأساسية.
- حالات البيانات والفراغ والخطأ.
- قواعد ظهور المؤشرات والدرجات والتوقعات.
- قائمة Frames المطلوبة للـwireframes ثم Figma.

### خارج النطاق

- تعديل Streamlit أو أي كود إنتاجي.
- تغيير الهوية البصرية أو CSS.
- إضافة تسجيل دخول، حفظ، تنبيهات، أو قدرات جديدة.
- تصميم High-Fidelity أو Design System.
- تغيير معادلات KPI المعتمدة.

## 3. تشخيص الحالة الحالية

### الهيكل المرصود

- شريط جانبي يجمع الحساب، الدور، الفلاتر، وحد العقود ومنهج الاتجاه.
- سبعة تبويبات رئيسية: قرار الاستثمار، تحليل الفرص، السوق والبدائل، مصادر البيانات، تقرير المخطط، خريطة الرياض، والمنصة.
- تبويبات فرعية داخل قرار الاستثمار للفرص، مقارنة الأحياء، وتوليد التقرير.
- خريطة وخرائط حرارية تظهر في أكثر من موقع.
- مولد تقرير داخل قرار الاستثمار، وتقرير مخطط كوجهة رئيسية مستقلة.
- محتوى تعريفي وتسويقي داخل مساحة العمل التحليلية.

### المشكلات الهيكلية

| المشكلة | أثرها على المستخدم | قرار الـIA |
|---|---|---|
| التنقل يخلط مهمة ووسيلة عرض ومخرجًا تسويقيًا | يصعب توقع مكان الوظيفة | اعتماد وجهات قائمة على نية المستخدم |
| صفحة قرار الاستثمار تجمع الفرص والتقييم والمقارنة والتقرير والتوقع | حمل معرفي ومسار طويل | فصل اكتشاف الفرصة عن تحليل الصفقة |
| المقارنة والخريطة والتقرير مكررة | أكثر من نقطة وصول بلا مصدر حقيقة واضح | وجهة واحدة لكل مهمة مع روابط سياقية |
| الفلاتر تبدو عالمية رغم اختلاف أثرها بين الصفحات | احتمال قراءة نطاق غير مقصود | فصل نطاق السوق عن مدخلات الصفقة |
| أسماء عربية وإنجليزية ورموز تعبيرية في مستوى واحد | ضعف الاتساق وسرعة المسح | العربية أساسًا، والإنجليزية كتسمية ثانوية عند الحاجة |
| «المنصة» والباقات داخل المنتج التشغيلي | انتقال مفاجئ من العمل إلى التسويق | نقلها إلى مساحة عامة خارج Workspace |
| الدور يغيّر تسميات التبويبات | يصعّب التعلم والعودة إلى نفس المكان | مسارات ثابتة مع ترتيب وأمثلة حسب الدور |
| الدرجة تظهر بصيغة `/100` قبل تفسير cohort والتصنيف | قد تبدو كتقييم مطلق | إظهارها كترتيب Inference مع cohort واضح |
| التوقع قريب من القرار الأساسي | قد يُقرأ كحقيقة مستقبلية | وضعه في طبقة ثانوية مع نتيجة الاختبار الرجعي |

## 4. مبادئ التجربة

1. **القرار قبل الرسم:** تبدأ الصفحة بالسؤال والنتيجة، ثم السبب، ثم الدليل.
2. **مهمة واحدة مهيمنة لكل صفحة:** لا تنافس صفقة محددة استكشاف السوق في المساحة نفسها.
3. **النطاق قبل الرقم:** المدينة والحي والنوع والفترة مرئية قبل أي KPI يتأثر بها.
4. **المرصود منفصل عن الاستدلال:** Raw وCalculated لا يختلطان مع Estimated وForecast وInference.
5. **التفاصيل تدريجية:** النتيجة أولًا، المنهج والمصدر عند الطلب، دون إخفاء قيد يغيّر القرار.
6. **مسارات ثابتة عبر الأدوار:** الدور يخصص البداية والسياق، لا يغير خريطة المنتج.
7. **مصدر حقيقة واحد لكل قدرة:** مقارنة واحدة، خريطة واحدة، ومركز تقارير واحد.
8. **لا ثقة عامة:** تستخدم «كفاية البيانات»، «جودة الاختبار الرجعي»، و«تحمل السيناريوهات» كمعانٍ منفصلة.

## 5. هرم المعلومات

كل شاشة قرار تتبع المستويات نفسها:

1. **L0 — السياق:** الدور، النطاق، الفترة، نوع العقار، آخر تحديث.
2. **L1 — النتيجة:** ماذا تقول البيانات الآن؟ وما الإجراء الأولي؟
3. **L2 — الأسباب:** العائد، السيولة، النمو، السعر، المخاطر، أو التغطية.
4. **L3 — الأدلة:** الاتجاه، المقارنات، الجداول، الخريطة، العقود، والمصادر.
5. **L4 — المنهج:** الصيغة، cohort، الأهلية، التصنيف، والقيود.

لا يجوز أن يبدأ المستخدم من L3 أو L4 في صفحة قرار ما لم يكن داخل «البيانات والمنهجية» أو في وضع الباحث.

## 7. التنقل العالمي

### التنقل الأساسي

| الوجهة | السؤال الذي تجيب عنه | نوع المحتوى |
|---|---|---|
| الرئيسية | ما أهم ما يستحق انتباهي الآن؟ | موجز + نقاط دخول |
| تحليل صفقة | هل أشتري هذا العقار، وبأي سعر؟ | قرار محدد ومدخلات |
| استكشاف السوق | ماذا يحدث في هذا السوق؟ | اتجاهات وشرائح وخريطة |
| المقارنة | أي حي أو شريحة أفضل ولماذا؟ | مقارنة متكافئة |
| التقارير | كيف أوثق وأشارك النتيجة؟ | مخرجات موجودة |
| البيانات والمنهجية | ما الذي يثبت هذا الرقم وما حدوده؟ | مصدر وتعريف وتغطية |

### قواعد التنقل

- ست وجهات كحد أقصى داخل مساحة العمل.
- لا تستخدم الرموز التعبيرية كهوية رئيسية للصفحة.
- الاسم الأساسي عربي؛ يمكن وضع المصطلح الإنجليزي داخل الصفحة، مثل `Opportunity Score`.
- يظل المسار ثابتًا عند تغيير الدور.
- روابط السياق مسموحة: «قارن هذا الحي»، «حلل صفقة في هذا الحي»، «أنشئ تقريرًا».
- الرابط السياقي ينقل الكيان والنطاق، ولا ينشئ نسخة ثانية من الأداة.

## 8. تخصيص الأدوار دون تفكيك الـIA

| الدور | صفحة البداية | الأولوية الأولى | الأولوية الثانية |
|---|---|---|---|
| مستثمر | تحليل صفقة | السعر والعائد والمخاطر | البدائل والتقرير |
| وسيط | الرئيسية | فرص العميل | المقارنة والتقرير |
| مطور عقاري | استكشاف السوق | الطلب والمزيج والنطاق | المقارنة والجدوى السوقية الموجودة |
| باحث | استكشاف السوق | الاتجاهات | البيانات والمنهجية |

التخصيص يقتصر في مرحلة الـBlueprint على:

- السؤال الرئيسي في رأس الصفحة.
- ترتيب نقاط الدخول في الرئيسية.
- الأمثلة والنص الإرشادي.
- KPI الثانوية الظاهرة أولًا.

## 10. Blueprint الصفحات

### 10.1 الرئيسية

**الهدف:** توجيه المستخدم إلى العمل التالي، لا إعادة عرض كل الرسوم.

الترتيب:

1. رأس سياقي: الدور، السؤال الرئيسي، النطاق الحالي، آخر فترة.
2. ثلاث نقاط دخول حسب الدور.
3. موجز سوق مختصر: 3–4 KPIs مرصودة أو محسوبة فقط.
4. 3 فرص تستحق الدراسة، موسومة `Inference`.
5. قيود تغير القرار: تغطية البيع، كفاية البيانات، جودة التوقع.
6. روابط إلى تحليل الصفقة أو الاستكشاف أو المقارنة.

لا يظهر في الرئيسية:

- محرك التقييم الكامل.
- جداول تفصيلية.
- خريطة كاملة.
- مولد تقرير كامل.

### 10.2 تحليل صفقة

**الهدف:** إنتاج قرار أولي لعقار محدد.

الترتيب:

1. مدخلات العقار الأساسية: المدينة، الحي، النوع، السعر، المساحة.
2. افتراضات الاستثمار والتمويل في Disclosure ثانوي.
3. قرار واضح: شراء / تفاوض / رفض، مع وصف أنه Estimated/Inference.
4. اقتصاديات الصفقة: العائد، التدفق، DSCR، سعر التعادل.
5. اختبار الضغط: تحمل السيناريوهات وحد الشراء.
6. مقارنة بيع مطابقة أو حالة «غير متاحة» مفسرة.
7. بدائل من النوع والنطاق نفسيهما.
8. توقع سنة داخل قسم ثانوي، مع كفاية التاريخ وخطأ الاختبار الرجعي.
9. تصدير تقرير الصفقة.

قاعدة UX: مدخلات الصفقة لا تتأثر بصمت بفلاتر استكشاف السوق.

### 10.3 استكشاف السوق

**الهدف:** فهم السوق واكتشاف الشرائح قبل اختيار صفقة.

الترتيب:

1. Scope bar ظاهر: المنطقة، المدينة، الحي، الفترة، النوع.
2. KPI strip: متوسط الإيجار المرجح، عقود آخر فترة، تغير ربعي متصل، التغطية.
3. الاتجاه الزمني مع حجم العقود.
4. تبديل داخلي بين:
   - الشرائح والفرص.
   - الخريطة.
   - التوزيع حسب النوع.
5. قائمة أو جدول النتائج.
6. Drawer / صفحة ملف الحي أو الشريحة.
7. إجراءات سياقية: قارن، حلل صفقة، أنشئ تقرير حي.

الخريطة ليست وجهة رئيسية مستقلة؛ هي View لنفس نتائج السوق ونفس النطاق.

### 10.4 المقارنة

**الهدف:** مقارنة كيانات متكافئة ضمن تعريف موحد.

الترتيب:

1. اختيار 2–4 أحياء أو شرائح.
2. شريط أهلية يثبت النوع والفترة والمستوى الجغرافي.
3. خلاصة الفائز حسب السؤال، لا فائز مطلق.
4. جدول مؤشرات موحد:
   - متوسط الإيجار.
   - عدد العقود.
   - النمو المتصل.
   - فجوة السعر من مرجع النوع نفسه.
   - Opportunity/Property Score كتقييم نسبي.
5. تفسير الفروق.
6. رابط لتحليل صفقة أو إنشاء تقرير مقارنة.

لا يسمح بمقارنة تبدو متكافئة إذا اختلف النوع أو الفترة دون تنبيه صريح.

### 10.5 التقارير

**الهدف:** جمع نقاط إنشاء وتصدير المخرجات الموجودة.

التنظيم:

- قرار صفقة.
- حي أو مخطط.
- مقارنة أحياء.
- تقرير محلل عقاري.

كل نوع يوضح قبل البدء:

- المدخلات المطلوبة.
- الفترة والنطاق.
- المؤشرات التي سيدرجها.
- التصنيفات والقيود.
- صيغ التصدير المتاحة حاليًا.

لا يبقى `AI Report Generator` تبويبًا داخل قرار الاستثمار.

### 10.6 البيانات والمنهجية

**الهدف:** تمكين التحقق دون إغراق مسار القرار.

الترتيب:

1. حالة البيانات: آخر فترة، عدد المصادر، التغطية.
2. القيود الحالية ذات الأثر:
   - البيع: مدينة واحدة وثلاثة أحياء ونوع واحد في اللقطة الحالية.
   - التوقع: خطأ رجعي مرتفع للطلب.
3. سجل المصادر الرسمية.
4. قاموس المؤشرات وتصنيفها.
5. قواعد الحبة، الفترات، الأهلية، وcohort.
6. تفاصيل التغطية حسب الفترة والمنطقة.

لا تعرض درجة ثقة رقمية غير معايرة للمصدر. تعرض حالة المصدر والتغطية والتصنيف المنهجي بدلًا منها.

## 11. عقد عرض المؤشرات في UX

### بطاقة KPI

كل بطاقة تتضمن:

- اسمًا لا يخلط بين الإيجار والبيع.
- قيمة ووحدة.
- فترة `as of`.
- نطاقًا مختصرًا.
- تصنيفًا: Raw / Calculated / Estimated / Forecast / Inference.
- مقارنة صريحة عند وجودها.
- حالة كفاية البيانات عند تأثيرها على القراءة.
- وصولًا إلى المصدر والتعريف.

### قواعد التصنيف المرئي

| التصنيف | مكانه الطبيعي | صياغة UX |
|---|---|---|
| Raw | KPI أساسي ودليل | «منشور من المصدر» |
| Calculated | KPI أساسي أو Driver | «محسوب وفق…» |
| Estimated | تحليل الصفقة | «تقدير مبني على افتراضات» |
| Forecast | قسم ثانوي | «سيناريو مستقبلي» + جودة الاختبار |
| Inference | ترتيب أو توصية أولية | «ترتيب نسبي داخل cohort» |

### Opportunity Score وProperty Score

- لا يوصفان كتقييم رسمي أو احتمال نجاح.
- يظهر نوع العقار والمستوى الجغرافي للـcohort.
- يفسر كل مكون ووزنه.
- لا تستخدم الدرجة وحدها لتوليد CTA شرائي حاسم.
- النص الافتراضي: «ترتيب استدلالي نسبي من 100 داخل مجموعة المقارنة الحالية».

### التوقع

- يبقى بعد الفعلي والمقارنة واختبار الضغط.
- تعرض كفاية التاريخ منفصلة عن الدقة.
- تعرض حالة `backtested_high_error` بلغة مفهومة.
- لا تستخدم كلمة «ثقة» وحدها.

## 12. الفلاتر والنطاق

### Scope السوق

- المنطقة.
- المدينة.
- الحي أو الموقع.
- الفترة.
- نوع العقار.
- حد العقود داخل إعداد متقدم.
- منهج الاتجاه داخل إعداد متقدم.

### Scope الصفقة

- حقول العقار والتمويل مستقلة.
- عند اختيار حي ونوع، يجلب النظام مرجع السوق المطابق.
- إذا تغير Scope السوق، لا تتغير الصفقة إلا بإجراء صريح.

### قواعد الظهور

- يظهر ملخص النطاق فوق كل مجموعة KPI.
- الفلتر العالمي لا يظهر في صفحات لا يغيرها.
- الفلاتر التي تخص مخططًا أو جدولًا توضع بجوار عنوانه.
- حالة «كل الفترات» لا تعرض كأنها فترة واحدة.

## 13. تدفقات المستخدم الأساسية

### تدفق المستثمر: هل أشتري؟

```text
الرئيسية → تحليل صفقة → إدخال العقار → قرار أولي
→ اقتصاديات ومخاطر → مقارنة مطابقة → بدائل
→ تقرير قرار
```

معايير النجاح:

- يرى القرار ومصدره قبل التمرير الطويل.
- يفرق بين مدخلاته وبين بيانات السوق.
- يفهم سبب عدم توفر مقارنة بيع عند غياب التطابق.

### تدفق اكتشاف فرصة

```text
الرئيسية → استكشاف السوق → تحديد Scope
→ قائمة الشرائح / الخريطة → ملف الشريحة
→ مقارنة → تحليل صفقة أو تقرير
```

### تدفق الوسيط

```text
الرئيسية → استكشاف السوق → اختيار مرشحين
→ المقارنة → تقرير عميل
```

### تدفق المطور

```text
استكشاف السوق → اتجاه الطلب والمزيج
→ ملف حي → المقارنة → تقرير نطاق / جدوى سوقية موجودة
```

### تدفق الباحث

```text
استكشاف السوق → الاتجاهات → ملف الشريحة
→ البيانات والمنهجية → تصدير البيانات أو التقرير المتاح
```

## 14. حالات UX المطلوبة

| الحالة | الرسالة المطلوبة | الإجراء المتاح |
|---|---|---|
| Loading | ما الذي يُحمّل وبأي نطاق | انتظار / إلغاء إن توفر |
| Empty scope | لا توجد بيانات للنطاق والفترة | توسيع النطاق أو الفترة |
| Insufficient sample | المقارنة غير مؤهلة بسبب حد العقود | إظهار الحد والسبب |
| Missing prior period | لا يوجد ربع سابق متصل | لا يعرض نموًا صفريًا |
| Sale unavailable | لا توجد مقارنة بيع مطابقة | شرح التغطية وعدم إدخال بديل غير متكافئ |
| Forecast limited | تاريخ أو اختبار غير كافٍ | إبقاء الفعلي وإخفاء الادعاء المستقبلي |
| Forecast high error | الاختبار الرجعي عالي الخطأ | عرض كسيناريو فقط |
| Stale data | الفترة أقدم من المتوقع | إظهار تاريخ المصدر |
| Source conflict | تداخل أو تعارض مصدر | إظهار قاعدة الأولوية والسجل المحتفظ به |
| Partial report | بعض الأقسام غير مؤهلة | تصدير مع الإفصاح عن النقص |

## 15. اللغة والتسمية

### قاموس التنقل

| الحالي | المقترح |
|---|---|
| قرار الاستثمار | تحليل صفقة عندما تكون المهمة عقارًا محددًا؛ الرئيسية للموجز |
| تحليل الفرص | استكشاف السوق / الشرائح والفرص |
| السوق والبدائل | استكشاف السوق + المقارنة |
| Sources / مصادر البيانات | البيانات والمنهجية |
| Investment Opportunities | الفرص الاستثمارية |
| AI Report Generator | إنشاء تقرير |
| تقرير المخطط | تقرير حي أو مخطط داخل التقارير |
| خريطة الرياض | الخريطة داخل استكشاف السوق |
| المنصة | عن قرينة خارج مساحة العمل |
| ثقة القرار | كفاية بيانات القرار |
| ثقة التوقع | كفاية التاريخ + جودة الاختبار الرجعي |

### قواعد المحتوى

- العربية هي اللغة الأساسية للتنقل والأزرار.
- المصطلح الإنجليزي يظهر عندما يكون اسم مقياس معتمدًا، وليس بدلًا عن واجهة عربية.
- لا تستخدم «أفضل» بلا تحديد المعيار.
- لا تستخدم «فرصة» بلا cohort وفترة.
- لا تستخدم «سعر عادل» إذا كان الناتج Estimate غير مطابق لبيع رسمي.
- لا تستخدم صياغة سببية أو تنبؤية من نمو تاريخي فقط.

## 16. الوصول والاستجابة

- كل حالة لونية لها نص أو رمز مفهوم مستقل عن اللون.
- لا يعتمد ترتيب البطاقات على اليمين/اليسار وحده.
- عناوين الأقسام تتبع تسلسلًا دلاليًا واضحًا.
- الجداول قابلة للقراءة في الهاتف عبر أولويات أعمدة، لا تصغير شامل.
- الخريطة لها بديل قائمة/جدول يعرض القيم نفسها.
- الأزرار تحمل أفعالًا محددة: «قارن الحي»، «حلل صفقة»، «أنشئ تقريرًا».
- النصوص العربية لا تختلط بعلامات وترقيم إنجليزية دون حاجة.

## 20. معايير اعتماد الـIA

تعتبر الـIA جاهزة للانتقال إلى Figma عندما:

- يستطيع كل دور تحديد صفحة البداية والمهمة الأساسية دون تغيير أسماء التنقل.
- يوجد موضع واحد فقط لكل من الخريطة والمقارنة والتقرير.
- لا تظهر أداة تسويقية كوجهة تشغيلية داخل Workspace.
- لا تختلط فلاتر السوق بمدخلات الصفقة.
- كل KPI ظاهر مرتبط بفترة ونطاق وتصنيف.
- الدرجات معرفة كـInference داخل cohort ثابت.
- التوقع موسوم بجودة الاختبار الرجعي، لا بكفاية التاريخ وحدها.
- حالات غياب البيع والنمو والفترة السابقة مصممة قبل الحالة المثالية.
- تغطي الـwireframes التدفقات الأربعة والحالات الست المشتركة.
